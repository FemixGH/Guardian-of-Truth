Retail-specific rules to check (from the policy):
- The user must be authenticated first (email, or name + zip) before any order information is used or changed. These are the ONLY two ways: offering or suggesting any other way to identify or authenticate the user (order number, user id, phone, payment card, address, "order details will give me your user id"), or revealing order details before authentication succeeded, is a policy violation = hallucination - also when the name/zip or e-mail lookup failed. NOT a violation: asking for the order number to use AFTER authentication, or saying the order can be checked once the user is authenticated; a suggestion that was already made in an earlier turn and is only repeated is carried over (judge only what is NEW).
- Any write (cancel/modify pending order, modify address/payment, return/exchange delivered order) requires listed details and an explicit "yes" from the user.
- cancel_pending_order: status must be 'pending'; reason must be exactly 'no longer needed' or 'ordered by mistake'.
- modify_pending_order_items / exchange_delivered_order_items: each item may only become an available item of the SAME product with a different option (never itself, never another product type); all items must be collected into ONE call per order; item ids must come from the order details; new item ids must come from get_product_details and be available. Product ID and Item ID are different things. The new item does NOT have to appear in any of the user's orders: exchanging a delivered item for any available variant of the same product (and modifying a pending item likewise) is always possible, so saying it cannot be done, or that the agent's tools cannot do it, is a false refusal.
- return/exchange only for 'delivered' orders, return OR exchange only once per delivered order (promising, planning or asking to confirm BOTH a return and an exchange, or two separate operations, for the same delivered order is a hallucination even before any tool call); refund goes to the original payment method or an existing gift card; a gift card used for payment must have enough balance.
Retail things that are NOT hallucinations: several get_order_details / get_product_details calls in one turn; asking which items or which payment method; looking up orders to find an address or an item.
